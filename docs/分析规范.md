# A股短线每日复盘：分析规范

这份文档给后续接手的写手或机器人用。目标不是“把数字填进页面”，而是做出与样板日同等质量的解读：**用数据推翻或校正表面现象，再给出可检验的次日观察**。对照样板：`notes/2026-08-03.json`（无 tick 的深度样板）和仓库外的 `2026-11-20` 竞价/tick 临时样板（有 tick 时必须达到的深度）。

页面是数据驱动的。人工贡献主要在 `notes/YYYY-MM-DD.json` 的文字，导出脚本负责数字、表格和事后回看。**先写 notes，再跑导出**，不要先出一份只有自动数字、没有解读的页面交差。

基于数据的分析框架，不构成投资建议。

---

## 1. 项目目标

- 面向新股民的短线复盘：看当天大盘、涨停梯队、题材、跌停、龙虎榜、情绪阶段，以及「次日观察」和带标注的「事后验证」。
- 白话简体中文。术语第一次出现时用括号或底部术语卡解释。颜色是红涨绿跌。
- 每个交易日页面末尾必须有一句：**基于数据的分析框架，不构成投资建议**。
- 默认筛选：市场统计（涨停家数、封板率、指数）按数据源原样；**观察名单、重点个股解读默认剔除科创板、北交所、ST，以及创业板 20cm 票**（除非它就是当天不可回避的事件，写进去时标明板块）。
- 禁止编造数字。没核实的标「待核」。不同口径并列，并写明出处。
- 当日解读只用当天收盘时能知道的信息；事后回看必须放在 `post`，并写明「事后才知道」。

## 2. 每日页面结构（与 DayView 一致）

导出后的当日页顺序如下，notes 的键要能对上。不要自创页面模块名。

| 顺序 | 页面区块 | notes 键 | 写什么 |
|---|---|---|---|
| 首页卡片 | 一句话 + 情绪标签 + 主看题材 | `headline`, `sentiment_tag` | 一句话要有判断，不要只报指数 |
| 文首 | 综述 | `summary` | 两三段 HTML 段落（可用 `<p>`、`<b>`），先给结论，再给关键数字 |
| 1 | 大盘概况 | `market` | 指数与个股是否打架、量能、涨跌家数、中位数、外部背景 |
| 2 | 涨停梯队 | `ladder` | 高度、梯队胖瘦、晋级率、高标板型（封板时间/开板次数/封单） |
| 3 | 题材板块 | `themes` | 哪条是真主线、哪条是跟风或一日游；自动归类漏了要手工补 |
| 4 | 跌停与亏钱效应 | `loss` | 亏的是谁、昨日涨停里谁跌得最狠、有没有成片核按钮 |
| 5 | 龙虎榜解读 | `lhb` | 游资与机构是否同向；榜面净买/净卖和全场感觉是否一致 |
| 6 | 情绪周期 | `cycle` | 先给判断，再列依据，最后用白话一句收束 |
| 7 | 次日观察要点 | `next`, `watch` | 只用当天能知道的信息；观察名单给理由 |
| 8 | 事后验证 | `post` | 必须标明事后；用来检验第 7 节的判断，不要改写第 7 节 |
| 9 | 术语小卡 | `terms` | 只填 `scripts/pipeline/terms.py` 里已有的词，没有的别硬塞 |
| 讯 | 当日消息面 | `news` | 每条带出处和 URL |
| 核 | 数据缺口 / 待核 | `gaps` | 口径冲突、缺数据、近似计算都写在这里 |

`summary`、`market`、`ladder` 等文字字段可以带少量 HTML（`<p>`、`<b>`）。导出时会剥掉标签，变成页面上的纯文本注释。

### 待拓展：竞价与 tick 模块（本轮不改 Vue 组件）

从 **2026-10-21** 起，东财本地逐笔覆盖范围内的交易日，解读必须增加「竞价」和「tick 资金流」两块分析（见第 3、4 节），用来拆高标、校正龙虎榜、判断主线含金量。

**现有 Vue 的 DayView 还没有竞价/tick 的独立 UI。** 在组件补上之前，把这些解读写进当日已有模块，不要另起一套页面结构：

- 高标竞价与盘中对比 → 写进 `ladder`
- 主线里谁在净买、涨停合计净流入 → 写进 `themes` 或 `ladder`
- 榜面净买但 tick 净卖（或相反）→ 写进 `lhb`
- 覆盖缺失、字段冲突 → 写进 `gaps`

等 Vue 增加竞价/tick 区块后，再把相应文字迁到新键；本规范不在这一轮改组件。

## 3. 数据源与拉取

### 3.1 扶摇（所有交易日的底盘）

接口基址是扶摇公开 API。密钥只从环境变量 `FUYAO_API_KEY`，或项目根目录已被 git 忽略的 `secrets/fuyao.key` 读取，**禁止写入 notes、facts、摘要、页面 JSON 或本规范**。

日常导出前设置（路径按运行环境填写，不要把某台机器的绝对路径写进仓库文档当唯一值）：

```bash
export FUYAO_API_KEY=...          # 或准备好 secrets/fuyao.key
export DAILY_REVIEW_ROOT=...      # 若指向已有 daily_review，会复用其 cache/ 与 notes/
export FUYAO_LHB_DIR=...          # 龙虎榜日榜 all / org / hot_money
export FUYAO_MARKET_DAILY=...     # 前复权日 K
export FUYAO_CACHE_DIR=...        # 接口缓存
```

更细的变量说明见 `scripts/pipeline/README.md`。

每个交易日至少拉取并交叉：

- 指数 K 线（上证、深成、创业板、科创50、北证50；成交额还要用深证综指）
- 涨停池 / 跌停池 / 炸板池
- 涨停统计（封板率、触及涨停家数、分板晋级率）
- 前复权日 K：涨跌家数、中位数、大涨大跌、昨日涨停溢价、晋级对照、个股估算成交额
- 龙虎榜日榜：`all`、`org`、`hot_money`（只取 1 日榜）
- 异动解读（跌停、大跌股的关键词，注明是 AI 汇总、以公告为准）

交易日历以扶摇指数 K 的日期为准，**不要猜节假日**。例如 2026 年 10 月第一个交易日是 **10 月 8 日**（国庆后），前一交易日是 9 月 30 日。

### 3.2 东财竞价与 tick（仅 2026-10-21 至覆盖期末）

覆盖范围以当日 `overview` 为准，不要假设某一天一定有数据。样板准备期间，覆盖约为 2026-10-21 至 2026-11-20 共 23 个交易日；若某日 `overview` 显示同步失败或部分缺失，要在 `gaps` 里写明，并降级为「无 tick 日」写法，不可编造 tick。

云端独立电脑**不能访问用户本机 localhost**。只使用用户当时提供的**公网入口和授权凭证**。每次请求必须带授权头，以及跳过隧道提示页所需的头。**不要把密钥、授权凭证或完整入口地址写进仓库或本规范**；换机器时向用户要当时的公网入口。

只读，先 `overview` 再决定拉哪一天：

- `GET /api/em-market/overview`：覆盖日期、同步是否完整
- `GET /api/em-market/day/YYYY-MM-DD`：当日涨停竞价与盘中摘要
- `GET /api/em-market/tick-flow/{code}`：如 `601138.SH`，单票连续竞价资金流
- 竞价明细还可读 `/api/limitup/auction`（按当日文档/概览提供的用法）
- 可选：`market-replay` 做回放核对
- 也可以看 `watchlist`、`universe`，视需要

**禁止** `POST .../sync/*`，禁止扫描全市场 parquet。

口径（必须写进有 tick 日的 `gaps`）：

- 买 `flag=2`，卖 `flag=1`
- **竞价不计入** tick-flow；tick-flow 只反映连续竞价
- 金额 = 价 × 量 × 100（A 股手/股换算）
- 涨停池与竞价列表、扶摇统计的家数可能不一致，并列写，不要偷偷改用一个数字

### 3.3 公开报道

收评、政策、公司公告用来补「为什么涨/跌」，必须带可点开的出处。数字仍以扶摇/日 K/tick 为准；媒体数字只做对照，放进 `news` 和 `gaps`。

## 4. 竞价 / tick 如何辅助解读（有覆盖日必须做）

有 tick 的日子，不要只把竞价涨幅、封单、净流入堆在表里。要用它们做三件事：**拆高标、认主线、校正龙虎榜**。

下面用 2026-11-20 的真例说明（数字以当日样板为准，转写时不要改口径）。

### 4.1 拆高标：竞价强不等于盘中强

11 月 20 日两只 4 板走法相反：

- **盛剑科技**：竞价封死，看起来是最强高标；盘中至少打开 3 次（开板次数字段 3 或 4，当时已标待核），14:07 才回封，tick 净卖 2.73 亿。
- **真视通**：竞价从涨停回落到只高开 +1.04%，开盘后全天没开、封单 1.59 亿，但 tick 仍净卖 2.48 亿。

结论不是“谁涨停谁强”，而是：**竞价最强的高标盘中更晃，竞价弱的高标反而封得死；两边连续竞价都在净卖。** 同一天还有毅昌科技竞价封死、开盘即塌、收盘大跌，用来对照“竞价封死”有多容易骗人。

无 tick 时，用扶摇的涨停时间、开板次数、封单金额、日 K 的开高低收做近似（见第 5 节），强度会弱一档，但思路相同。

### 4.2 认主线：跟风少、封单和 tick 同向的，才更像主线

11 月 20 日表面高度在盛剑（电子化学品），但：

- 唯一非 ST 的 2 板是 **中京电子**（PCB），封单全场最大（2.04 亿），全天未开，tick 略净买 0.13 亿，也是当天仅有的 1 进 2（不含 ST 约 5.6%）。
- 当天 28 只涨停 tick 合计净卖 25.14 亿，只有 5 只净买，几乎都在 PCB/液冷/算力链上；冰山冷热成交和净买都靠前。

所以主线更像 PCB/液冷/算力，而不是盛剑这支电子化学品。**高度票所在的题材，不一定是资金真正愿意加仓的题材。**

### 4.3 校正龙虎榜：前五席位不是全场

11 月 20 日东方海洋、华微电子等在龙虎榜上显示净买，tick 却是大净卖。要写出来：前五席位和全场不是一回事。有 tick 日必须做这一步；无 tick 日至少指出榜面分类（机构/游资）和净额口径的局限。

### 4.4 写的时候注意

- 先概述当日 tick 拉取是否完整、耗时（便于以后判断能不能全量用），再进入解读。
- 字段冲突（开板次数 3 或 4、不同接口涨停家数不一致）标待核，不要选一个假装唯一。
- 不要把竞价的买卖算进 tick-flow，再拿去和盘中净额比。

## 5. 无 tick 日怎么做到同等深度

2026-10-20 及更早、以及覆盖缺失的日子，没有东财竞价/tick。**深度不能因此降档。** 用扶摇和日 K 逼近第 4 节的三件事：

1. **板型代替竞价/盘中拆解。** 对空间板和 2 板以上，至少写：涨停时间（09:25 是否竞价封死）、开板次数、封单金额、日 K 开高低收（是否一字、是否盘中深砸再回封）、成交额。例如 2026-10-08 的新华传媒是竞价封死的缩量一字（成交只有约 0.64 亿、封单约 17.76 亿），上海洗霸虽晋级 3 板却开板 10 次、封单只有 0.14 亿——晋级成功和板型质量不是一回事。
2. **晋级率要拆开写。** 不要只报“连板晋级率”。必须同时给 **1 进 2**（分母用昨天可交易首板，注明是否含 ST、是否扣停牌）和 2 进 3、3 进 4……以及「昨天连板股今天平均涨幅」。2026-10-08 的连板晋级约 7/12=58%，但 1 进 2 只有约 7%：表面情绪还行，低位接力已经失效。
3. **溢价和亏钱效应。** 昨日涨停今天平均涨幅、上涨/下跌家数；昨日连板股与昨日首板是否分化。高位还在赚钱、低位大面积溢价为负，就是“抱团”而不是普涨修复。
4. **龙虎榜拆游资与机构。** 同一只票两边同向叫合力，反向叫分歧。尤其要找「榜面净买但股价跌停/大跌」或「机构大卖、游资大买」。没有 tick 时，这是校正榜面的主要方法。
5. **高标对比。** 至少对比空间板和次高标：谁是一字、谁是换手、谁断板、断板是核按钮还是高位震荡。不要把“高度还在创新高”直接写成情绪转强。
6. **日 K 近涨停但池里没有的票。** 可能是差一分钱或前复权误差，标待核，不要擅自算进涨停家数，也不要写成大跌断板。

无 tick 不是借口省略模块。`market` 到 `gaps` 仍要全部写完。

## 6. 情绪周期框架

先看自动规则（`helpers.auto_stage`）给出的标签和四条依据，再人工判断。自动规则是助手，不是结论。样板里 8/3 自动偏「分歧（高位断板，低位仍有承接）」，人工写成「分歧偏修复」；11-20 封板率回到 80%，但不能写成转强，因为 1 进 2 极低、个股大面积下跌。

常用阶段（标签尽量短，细节放 `cycle` 正文）：

- **高潮**：涨停很多、封板率高、昨日涨停溢价高、高度还在抬。仍要检查 1 进 2 和主线是否只是首板爆炸。
- **发酵 / 修复**：涨停和溢价回升、跌停不多、高位没有成片核按钮。
- **分歧**：指标打架。典型是指数跌但个股涨，或高度上升但 1 进 2 极低，或封板率修复但亏钱效应集中在某一条老主线。
- **退潮 / 冰点**：高度下台阶且溢价为负，或跌停大量出现、昨日涨停普遍亏钱。

写作顺序建议：

1. 一句话判断（不要只复制自动标签）。
2. 三条以上依据，每条都有数字。
3. 白话收束：市场在做什么、第二天看什么才能验证。

注意「节后首日、除权日、新股上市、大票停牌」会造成高度或家数的被动变化，要写清楚。

## 7. 口径冲突怎么写

原则：**数字不以「待核」代替已有数据；不同口径并列，写明出处和算法。**

常见冲突（示例，写当日报告时换成当天数字）：

- **涨停家数**：扶摇涨停池（可含 ST）vs 扶摇统计（常不含 ST）vs 证券时报·数据宝 vs 东财竞价列表。封板率分母（触及涨停或炸板+封住）也可能不同。8/3 是扶摇不含 ST 75、封板率 82.4%（75/91），数据宝 83 只、封板率 79.05%。10/8 是扶摇不含 ST 42、含 ST 44、统计封板率 56.8%（42/74），数据宝 45 只涨停、39 只封板未遂、封板率 53.57%。
- **涨跌家数**：本机前复权日 K 默认只含沪深、不含北交所；媒体「全市场」通常含北交所。
- **成交额**：本项目三市成交额 = 上证综指 + 深证综指 + 北证50 成交额（北证用北证50 近似）。媒体常报「沪深两市」或「全市场」，差一个北证量级。
- **晋级率**：扶摇 `page_boards` 的 promotion_rate，与用前后两天涨停池自己对出来的比例，分母（是否含 ST、是否扣停牌）可能不同，要自己算一遍并写分母。
- **个股成交额**：日 K 成交量 × 前复权收盘价，只作相对排序。
- **龙虎榜**：扶摇（同花顺口径）1 日榜，不是交易所全部上榜股；没有逐席位全部明细。游资外号是扶摇分类，不代表真实身份。
- **题材家数**：按涨停原因关键词自动归类，一只票可属多个题材，加总会大于涨停总数；关键词表会漏（如 2026-10-08 以前的版本几乎收不到「固态电池」）。手工补的主题要声明是手工口径。
- **开板次数 / 日 K 是否一字**：扶摇 `open_times` 为空不代表没开板；要用日 K 高低价核对，冲突标待核。

## 8. 导出与推仓步骤

在仓库根目录、环境变量已就绪时：

1. 把人工解读写成 `notes/YYYY-MM-DD.json`（项目根 `notes/`）。若设置了 `DAILY_REVIEW_ROOT` 且该目录下已有 `notes/`，导出会**优先读那里**，所以两处都要放同一份，避免改了一边、导出还用旧稿。
2. 键名必须能被现有 DayView 消费：`summary`, `headline`, `sentiment_tag`, `market`, `ladder`, `themes`, `loss`, `lhb`, `cycle`, `next`, `watch`, `post`, `terms`, `news`, `gaps`。列表字段用字符串数组；`watch` 为 `{code,name,why}`；`news` 为 `{point,src,url}`。
3. 导出：

```bash
python3 scripts/export_day.py YYYY-MM-DD
```

默认事后回看 5 个交易日（可用 `--post` 改）。脚本写入 `public/data/days/YYYY-MM-DD.json`，并更新 `public/data/manifest.json`。首页日历会自动出现这一天。

4. 自查：JSON 能被 DayView 打开；`manifest.json` 含这一天；文件里没有密钥、授权凭证、接口入口地址。
5. 同期建议在复盘工作目录留下 `facts.json` 和 `摘要.md`，方便对数字、口径和待核做追溯。摘要末尾同样加投资声明。
6. **推到 GitHub 必须单独得到用户明确授权。** 未授权时只准备好变更，不要 `git push`。即使授权，也不要提交 `secrets/`、`.env`、接口缓存、`node_modules`、`dist/`。提交信息示例：`data: 更新 YYYY-MM-DD 复盘`。分析规范本身的提交可以写 `docs: 增加分析规范`。

字段样例见 `public/data/_fixture.example.json`（不会作为真实交易日出现）。

## 9. 禁忌

- 编造或四舍五入到「看起来更整齐」的关键数字；不确定就写原值和待核。
- 把事后信息写进 `market` / `ladder` / `next`。8/3 样板里写过 8/4 涨停 137 只，那是事后验证；做 8/4 当日必须用 8/4 自己的数据重核，禁止照抄。
- 用「封板率回升」「高度创新高」「连板晋级率过半」单独宣布转强，而不看 1 进 2、溢价结构和亏钱效应。
- 把自动题材榜第一名直接当主线；关键词漏掉时要手工补，并在 `gaps` 说明。
- 观察名单塞进科创 / 北交 / ST / 创业板 20cm（除非必须提及且标明）。
- 在仓库、notes、facts、摘要、规范里写入 API 密钥、授权凭证、接口入口地址、用户本机绝对路径。
- 对东财数据做 `POST /sync/*` 或扫描全市场 parquet。
- 在云端尝试访问用户本机 localhost 上的东财服务。
- 未获用户明确要求就 `git push`、发消息或改远程仓库。
- 输出投资建议口吻（“建议买入/卖出”）。可以写「次日观察」，必须声明不构成投资建议。
- 为赶进度省略 `lhb`、`loss`、`gaps` 或把 `post` 留空却假装做完了一日。

## 10. 检查清单（写完一日必过）

- [ ] 交易日已用日历核对，不是猜的节假日顺延。
- [ ] 先 overview（若是 tick 覆盖期），再决定用 tick 还是无 tick 写法；没有数据就降级并在 `gaps` 说明。
- [ ] `headline` 有判断；`summary` 先结论后数字；语气白话。
- [ ] 大盘：指数、三市成交额及同比、涨跌家数、中位数、涨停/跌停/炸板、封板率，均有口径。
- [ ] 梯队：高度是谁、是否一字/竞价、封单和开板次数、1 进 2 及更高晋级率的分母。
- [ ] 题材：指出真主线与假高度；自动归类遗漏已手工补。
- [ ] 亏钱效应：跌停结构、昨日涨停最差表现、是否成片核按钮。
- [ ] 龙虎榜：机构/游资同向或反向；有 tick 时与 tick 净额对照。
- [ ] 有 tick 日：高标竞价 vs 盘中、涨停合计净流入、至少一处榜面与 tick 的矛盾（若存在）。
- [ ] 情绪判断与自动标签若不同，写清为什么。
- [ ] `next` / `watch` 不含事后信息；观察名单已剔科创/北交/ST/创业板 20cm。

- [ ] 未在未授权的情况下 git push。

## 11. 质量对照（什么叫“够格”）

够格的一日，读完应能回答：

- 今天表面上是什么？（指数、涨停数、封板率、高度）
- 这个表面哪里不成立？（例如封板率回升但 1 进 2 极低；竞价最强的高标盘中净卖；政策首日涨停潮没有梯队）
- 真主线是哪一条、依据是什么？
- 明天用哪几件事就能证伪今天的判断？

不够格的表现：只堆表格；把自动标签当结论；把媒体「超百股涨停」和扶摇口径混用还不说明；把次日才知道的涨停数写进当日综述。

先求一日质量，不要为了赶进度并行下一天。
